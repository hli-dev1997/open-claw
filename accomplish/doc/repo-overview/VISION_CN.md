## OpenClaw 愿景

OpenClaw 是一个真正能办成事的 AI。
它运行在你的设备上，在你使用的渠道中，遵循你自己的规则。

本文档阐述项目的当前状态和发展方向。
我们仍处于早期阶段，因此迭代速度很快。
项目概览和开发者文档：[`README.md`](README.md)
贡献指南：[`CONTRIBUTING.md`](CONTRIBUTING.md)

OpenClaw 最初是一个个人实验场，用于学习 AI 并构建真正有用的东西：
一个能够在真实计算机上执行真实任务的助手。
它经历了几个名称和外壳的演变：Warelay -> Clawdbot -> Moltbot -> OpenClaw。

目标：一个易于使用、支持广泛平台、并尊重隐私和安全的个人助手。

当前的关注重点：

优先级：

- 安全和安全的默认设置
- 缺陷修复和稳定性
- 安装可靠性和首次运行体验

下一步优先级：

- 支持所有主要模型提供商
- 改进对主要消息渠道的支持（并增加一些高需求渠道）
- 性能和测试基础设施
- 更好的计算机使用能力和智能体编排能力
- CLI 和 Web 前端的易用性
- macOS、iOS、Android、Windows 和 Linux 上的伴侣应用

贡献规则：

- 一个 PR = 一个问题/主题。不要捆绑多个不相关的修复/功能。
- 超过约 5,000 行变更的 PR 仅在特殊情况下进行审查。
- 不要一次性提交大量小型 PR；每个 PR 都有审查成本。
- 对于非常小的相关修复，鼓励合并到一个有针对性的 PR 中。

## 安全

OpenClaw 的安全性是一种经过刻意权衡的结果：强大的默认设置同时不牺牲能力。
目标是在实际工作中保持强大功能，同时让风险路径明确且由操作员控制。

规范的安全策略和报告方式：

- [`SECURITY.md`](SECURITY.md)

我们优先考虑安全的默认设置，同时也为可信的高权限工作流提供清晰的可调节开关。

## 插件与记忆

OpenClaw 拥有广泛的插件 API。
核心保持精简；可选能力通常应以插件形式提供。
我们总体上正在精简核心，同时扩展插件的能力范围。
如果某个有用的功能还不能作为插件实现，我们欢迎通过 PR 和设计讨论来扩展插件 API，而不是添加一次性的核心行为。

有两种主要的插件风格：

- 代码插件运行 OpenClaw 插件代码，适合更深层次的运行时扩展。
- 捆绑式插件打包稳定的外部接口，如技能、MCP 服务器和相关配置。

当捆绑式插件能够表达所需能力时，优先使用它们。
它们具有更小、更稳定的接口和更好的安全边界。
当能力需要运行时钩子、提供商、渠道、工具或其他进程内扩展点时，使用代码插件。

推荐的插件路径是通过 npm 包分发，同时在开发时支持本地扩展加载。
如果你构建了一个插件，请在你的自有仓库中托管和维护它。
将可选插件添加到核心的门槛故意设置得很高。
插件文档：[`docs/tools/plugin.md`](docs/tools/plugin.md)
插件发现、官方发布者状态、来源验证和安全审查位于 [ClawHub](https://clawhub.ai/)。
OpenClaw 文档应记录核心扩展点；插件推广应归属于 ClawHub，对于官方插件，最好在经过审核的组织发布者名下进行。

记忆是一个特殊的插件槽位，同一时间只能有一个记忆插件处于活动状态。
目前我们提供了多种记忆选项；随着时间的推移，我们计划收敛到一个推荐的默认路径。

### 技能

我们仍然提供一些内置技能以保证基础用户体验。
新技能应首先通过 [ClawHub](https://clawhub.ai/) 发布，而不是默认添加到核心中。
官方或内置推广需要有明确的产品、安全或维护者所有权方面的理由。

### MCP 支持

OpenClaw 同时支持作为服务器和运行时集成接口的 MCP。
MCP 的详细信息位于 [`docs/cli/mcp.md`](docs/cli/mcp.md)。

项目的目标是提供实用的 MCP 支持，同时避免重复现有的智能体、
工具、ACPX、插件或 ClawHub 路径。

### 安装设置

OpenClaw 目前在设计上以终端为先。
这使安装过程清晰明确：用户能直接看到文档、认证、权限和安全状态。

长期来看，我们希望在安全加固成熟后提供更简便的入门流程。
我们不希望通过便利化包装来隐藏关键的安全决策。

### 为什么选择 TypeScript？

OpenClaw 本质上是一个编排系统：提示词、工具、协议和集成。
选择 TypeScript 是为了让 OpenClaw 默认即可被修改。
它被广泛认知，迭代速度快，并且易于阅读、修改和扩展。

## 我们暂时不会合并的内容

- 可以在 [ClawHub](https://clawhub.ai/) 上发布的新核心技能
- 所有文档的完整翻译集（已推迟；我们计划后续使用 AI 生成翻译）
- 不符合模型提供商类别的商业服务集成
- 在已有支持的渠道基础上，没有明确能力或安全差距的包装渠道
- 重复现有 MCP、ACPX、插件或 ClawHub 路径且没有明确产品或安全差距的 MCP 工作
- 智能体层级框架（管理器之管理器 / 嵌套规划器树）作为默认架构
- 重复现有智能体和工具基础设施的重量级编排层

这份列表是路线图的护栏，而非物理定律。
强烈的用户需求和坚实的技术理由可以改变它。
